Lesson 1

What JavaScript is, and how to run it

JavaScript is the language that makes web pages do things: react to clicks, validate forms, fetch data, draw games. It runs inside every browser, and also on servers (via Node.js), phones, and desktop apps. If you learn one language for the web, learn this one.

A program is just a list of instructions executed top to bottom. The most useful instruction while learning is console.log(...) — it prints whatever you give it.

Your turn

Print your own name, then print your favourite number added to 10.

Where else can you run JS?

1. This page — the Run buttons. 2. Any browser — press F12 (or Cmd+Opt+J on Mac) to open the DevTools console and type code there. 3. Node.js — install it, then node file.js.

Two rules for the editors here: Ctrl/Cmd+Enter runs the code, and avoid writing a loop that never ends (while (true)) — it would freeze the tab.

Lesson 2

Variables — naming your data

A variable is a labelled box holding a value. You create one with let (reassignable) or const (permanent). var is the ancient version — you'll see it in old code, but don't write it.

  • const by default. Switch to let only when the value must change.
  • Names are case-sensitive, can't start with a digit, and shouldn't contain spaces — use camelCase like userAge.
  • = means "put this value in that box". It is not "equals" (that's ===).

Lesson 6

Booleans and decisions

if runs code only when a condition is true. Comparisons produce booleans.

  • Use === and !== (strict) — never == / !=, which do weird type coercion.
  • && = "and", || = "or", ! = "not".
  • The ternary cond ? a : b is a one-line if/else that produces a value.

Lesson 10

Functions — packaging up logic

A function takes inputs (parameters), does work, and gives back a result with return. Writing one turns 10 lines into a name — that's the whole point.

  • No return means the function gives back undefined.
  • return also stops the function immediately.
  • Variables created inside a function live only inside it (that's scope).
  • Arrow functions const add = (a, b) => a + b; are the modern short form. If the body is one expression, no braces and no return needed.

Lesson 12

Errors and debugging

Errors are information, not failure. The trick is learning to read them.

  • ReferenceError — you used a name that doesn't exist. Almost always a typo or a variable used before it's created.
  • TypeError — you asked a value to do something it can't, like undefined.name.
  • SyntaxError — the code didn't even parse. Usually a missing ), }, or quote.

When something misbehaves: log the value right before the crash, and read the message from the end backwards — it usually names the exact problem.

Debugging habit: add console.log("here", someValue) and run again. Confirm what you believe is true. Half of all debugging is discovering your assumption was wrong.
